# المساعد الذكي — Smart Assistant

تطبيق ويب حقيقي (PWA) لإدارة العملاء والأرصدة والاستحقاقات والمخزون، مع محرك استيراد ذكي من Excel وCSV وPDF وقواعد بيانات SQLite/DB، مبني بمبدأ **عدم فقدان البيانات (Zero Data Loss)**.

التطبيق عام ومستقل — لا يحتوي على اسم أي محل أو بيانات ثابتة. كل بيانات المحل تُدخل من شاشة **الإعدادات**.

---

## 1. التشغيل (Run)

لا يحتاج إلى Build خطوة أو Node.js. هو HTML/CSS/JS ثابت بالكامل.

**الطريقة الأسهل (محليًا):**
```bash
cd smart-assistant
python3 -m http.server 8080
# ثم افتح المتصفح على http://localhost:8080
```
(لا يمكن فتح `index.html` مباشرة بنقرتين على بعض المتصفحات لأن IndexedDB وService Worker يحتاجان بروتوكول http/https وليس file://)

**لماذا سيرفر محلي بسيط؟** لأن هذا هو المطلوب فقط لتقديم الملفات الثابتة — لا يوجد أي منطق خادم (Backend) في هذا الإصدار؛ كل المنطق والبيانات في المتصفح.

## 2. النشر (Deploy)

ارفعي مجلد `smart-assistant` كما هو على أي استضافة ملفات ثابتة تدعم HTTPS (شرط ضروري لتشغيل Service Worker وInstall):
- GitHub Pages
- Netlify / Vercel (استضافة ثابتة، بدون إعدادات بناء)
- أي استضافة تقليدية (رفع عبر FTP لمجلد عام)

بعد النشر على HTTPS: افتحي الرابط من هاتف أندرويد → ستظهر رسالة "إضافة إلى الشاشة الرئيسية" (Install) تلقائيًا من المتصفح — هذا تثبيت PWA حقيقي.

## 3. البناء الإنتاجي (Production Build)

لا يوجد خطوة Build لأن الكود مكتوب مباشرة بدون Framework (لا React/Vue/Webpack) — هذا مقصود لإبقاء المشروع بسيطًا وقابلاً للتشغيل فورًا دون أدوات بناء. مجلد `smart-assistant` نفسه هو نسخة "الإنتاج" الجاهزة للنشر.

## 4. البنية التقنية (Architecture)

```
smart-assistant/
├── index.html            الهيكل الرئيسي + تحميل مكتبات CDN
├── manifest.json          بيانات PWA
├── sw.js                  Service Worker (تخزين مؤقت للعمل Offline)
├── css/style.css          التصميم (عربي RTL، فاتح/داكن)
├── icons/                 أيقونات PWA
└── js/
    ├── db.js               طبقة قاعدة البيانات (IndexedDB) — جداول، Indexes، مطابقة تكرار
    ├── import.js            محرك الاستيراد (Excel/CSV/PDF/SQLite) بمبدأ Zero Data Loss
    ├── modules.js           منطق العملاء/المخزون/التذكيرات/العملاء المنسيين
    ├── reports-backup.js    التقارير (PDF/Excel/CSV) + النسخ الاحتياطي/الاستعادة
    ├── assistant.js         المساعد الذكي (محلي، يستعلم من بياناتك الفعلية)
    └── app.js                الواجهة والتوجيه (Router) وكل الشاشات
```

**قاعدة البيانات:** IndexedDB حقيقية بجداول منفصلة (customers, items, categories, units, settings, activityLog, backups, importBatches, reviewQueue, users) مع Indexes على الحقول المستخدمة في البحث/الفلترة، ومنع التكرار عبر مطابقة (المعرّف الأصلي ← الهاتف ← الكود ← الاسم ← مطابقة تقريبية).

**لا يوجد سيرفر خلفي (Backend)** في هذا الإصدار — كل شيء يعمل داخل متصفح المستخدم. هذا خيار مقصود ليكون التطبيق قابلاً للتشغيل فورًا بدون استضافة قاعدة بيانات، لكنه يعني أيضًا:
- البيانات محفوظة على هذا الجهاز/المتصفح فقط (لا مزامنة تلقائية بين الأجهزة). للمزامنة بين عدة أجهزة يلزم إضافة سيرفر + قاعدة بيانات مركزية لاحقًا.
- نظام "المستخدمون والصلاحيات" يتحكم بالواجهة فقط، وليس حماية أمنية فعلية (موضّح داخل شاشة المستخدمين بالتطبيق نفسه أيضًا).

## 5. مبدأ عدم فقدان البيانات (Zero Data Loss) — كيف تحقق فعليًا

- كل سجل مستورد يحتفظ بـ`raw` (النص الأصلي كما هو من الملف) و`parsed` (القيمة المستخرجة)، وحتى لو فشل `parsed`، يبقى `raw` محفوظًا في `rawName` / `rawBalance` / `rawQty`.
- لا يوجد أي Regex يحذف أرقامًا أو رموزًا من اسم صنف أو عميل — أسماء الأصناف تُنسخ كما هي بالكامل، بما فيها الأرقام والمقاسات والرموز (`×`, `/`, `*`, إلخ).
- الرصيد السالب يبقى سالبًا؛ لا يوجد أي تحويل لصفر في أي مسار من مسارات الكود (`parseBalanceCell`, `mergeCustomer`, `saveCustomer`).
- صفوف الإجمالي/الترويسة/التذييل يتم تجاهلها بالاسم عبر قائمة كلمات مفتاحية (`IGNORE_ROW_HINTS`) وليس بحذف البيانات، بل بوضعها في قائمة "متجاهل" قابلة للعرض والمراجعة.
- أي استيراد يأخذ نسخة احتياطية تلقائية كاملة قبل التنفيذ؛ إذا فشل التنفيذ أثناءه، يتم **Rollback** كامل لاستعادة الحالة السابقة (`Import.commitImportPlan`).
- المطابقات غير المؤكدة (ثقة أقل من 90%) لا تُدمج تلقائيًا — تذهب إلى "قائمة المراجعة" وينتظر قرار المستخدم.

## 6. حدود حقيقية يجب معرفتها (بصراحة تامة، بدون تجميل)

| الميزة | الحالة الفعلية |
|---|---|
| استيراد Excel/CSV | ✅ حقيقي بالكامل، يعمل فورًا |
| استيراد PDF نصي (فيه نص حقيقي) | ✅ حقيقي، استخراج نص فعلي عبر pdf.js |
| استيراد PDF ممسوح ضوئيًا (صور) | ❌ غير مدعوم — يحتاج OCR بخدمة خارجية لم تُدمج؛ التطبيق يكتشف هذه الحالة ويوقف الاستيراد صراحة بدل التظاهر بالنجاح |
| استيراد SQLite/DB | ✅ حقيقي عبر sql.js (WASM) داخل المتصفح، مع تجاهل الجداول المحاسبية تلقائيًا |
| النسخ الاحتياطي/الاستعادة | ✅ حقيقي، يشمل كامل قاعدة البيانات |
| التقارير PDF/Excel/CSV | ✅ تصدير حقيقي وقابل للتحميل |
| تنبيهات المتصفح (Notification) | ✅ حقيقية عند منح الإذن؛ إن رُفض الإذن، يبقى التنبيه داخل التطبيق فقط (Toast) بدل التظاهر بأنه أُرسل |
| PWA / Install / Offline | ✅ حقيقي بعد أول زيارة أونلاين (لتخزين الملفات مؤقتًا)؛ أول فتح بدون إنترنت لن يعمل لأن شيئًا لم يُخزَّن بعد |
| WhatsApp | ✅ حقيقي عبر `wa.me`، يفتح واتساب برسالة جاهزة معبأة تلقائيًا |
| المساعد الذكي | ✅ حقيقي لكنه **محلي** (استعلام مباشر من بياناتك، ليس نموذج لغة). ربطه بنموذج LLM حقيقي يحتاج سيرفر وسيط لحماية مفتاح API وتفادي قيود CORS — غير مُنفَّذ في هذا الإصدار |
| الصلاحيات (Users & Roles) | ⚠️ تتحكم بالواجهة فقط؛ ليست حماية أمنية حقيقية بدون سيرفر خلفي |
| مزامنة بين أجهزة متعددة | ❌ غير موجودة في هذا الإصدار (بيانات كل جهاز محلية له) |

## 7. اختبار ذاتي تم إجراؤه قبل التسليم (مطابقة لقائمة الاختبارات الـ25)

- ✅ فحص الكود: لا يوجد Regex يحذف حروفًا/أرقامًا/رموزًا من أسماء الأصناف (`import.js`, دالة `parseQtyCell`/معالجة الاسم تنسخ القيمة كما هي)
- ✅ المقاسات والنص العربي يُنسخ حرفيًا (`raw.name`, `parsed.name` بدون أي `.replace` على الاسم)
- ✅ العملاء أصحاب الرصيد السالب يُستوردون ويبقى الرصيد سالبًا (`parseBalanceCell` لا يقلب الإشارة أبدًا)
- ✅ لا يوجد أي مسار كود يحوّل رصيدًا سالبًا لصفر
- ✅ منع التكرار عبر `findCustomerByMatch`/`findItemByMatch` بأولوية: معرّف أصلي → هاتف → كود → اسم مطابق → اسم تقريبي
- ✅ صفوف الإجمالي/الترويسة/اسم المحل/رقم الهاتف بالهيدر تُستبعد عبر `IGNORE_ROW_HINTS` قبل اعتبارها عميلًا
- ✅ تحديث الرصيد لا يمسح تاريخ الاستحقاق أو الملاحظات أو تاريخ آخر متابعة (`mergeCustomer` يحافظ عليها صراحة)
- ✅ تحديث كمية المخزون لا ينشئ أي حركة مبيعات (لا يوجد جدول مبيعات أصلًا في المخطط)
- ✅ "تمت المتابعة" لا تغيّر الرصيد ولا تنشئ حركة مالية (`markFollowedUp`)
- ✅ Backup تلقائي قبل كل استيراد + Rollback كامل عند الفشل (`commitImportPlan`)
- ✅ جميع ملفات JS اجتازت فحص الصياغة (`node --check`) بدون أخطاء
- ⚠️ اختبارات تتطلب متصفحًا فعليًا لتأكيدها ميدانيًا (لم يُتح تنفيذها آليًا في بيئة البناء هذه): عمل Offline الكامل، التثبيت الفعلي على هاتف، أداء الاستيراد مع ملفات ضخمة جدًا (آلاف الصفوف)، تنبيهات المتصفح الفعلية. يُنصح باختبارها بعد النشر على استضافة HTTPS حقيقية.

---

## 8. ما لم يُبنَ بعد (نطاق للمرحلة القادمة)

هذا إصدار أول (MVP) حقيقي وكامل الوظائف الأساسية، وليس كل تفصيل من المواصفة الأصلية الضخمة مُنفَّذ بنفس العمق. التالي لم يُبنَ بعد وواضح أنه غير موجود (لا يوجد أي زر أو ادعاء وهمي عنه):
- OCR لملفات PDF الممسوحة ضوئيًا
- تعلّم آلي لتحسين دقة الاستيراد من تصحيحات المستخدم مع الوقت
- سيرفر خلفي لمزامنة متعددة الأجهزة وصلاحيات أمنية حقيقية
- ربط مساعد ذكاء اصطناعي حقيقي (LLM) — يحتاج سيرفر وسيط

أخبريني بأي من هذه تريدين أن نبنيه تاليًا وسأكمل عليه.
